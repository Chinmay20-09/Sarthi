# Developer documentation

Use these documents to learn how Sarthi works and how to change it.

| Document | Use it to |
| --- | --- |
| [Architecture](ARCHITECTURE.md) | Read the current system design and request flow. |
| [Project State](PROJECT_STATE.md) | Check what is complete, partial, or planned. Read this before you start work. |
| [Development](DEVELOPMENT.md) | Set up the project and follow development rules. |
| [Testing](TESTING.md) | Run tests and review test limits. |

## Rules

- Treat the code as the source of truth. Link each architecture claim to code.
- Mark each feature as implemented, partial, or planned.
- Do not describe planned work as complete.
- Update the relevant document when code changes affect it.
- Put superseded documents in `docs/archive/`. Do not edit archived history.

Use `docs/client/` to learn how to use Sarthi. Use `docs/dev/` to learn how it works. Use `docs/agent/` for short-term coding context.
